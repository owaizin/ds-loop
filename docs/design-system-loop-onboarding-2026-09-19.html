Exact acquisition handoff

Website → Get started → run in the target repository:

npm install --save-dev ds-loop
npx ds-loop --help

Then open a file-capable coding agent in that same repository and send:

Read node_modules/ds-loop/skill/SKILL.md.
Help me get started with this repository.
Understand what I want to improve, inspect relevant evidence,
then explain the diagnosis and recommend a bounded first delivery.
Do not start a broad migration.

This is an explicit activation prompt, not a new command. npm installs files; the agent executes the skill's guidance.

Gaps in the current experience

  1. Website setup is stale. The local page still leads through clone/build and a 0.1.0 tarball; the installation guide is npm-first.
  2. Activation is a separate handoff. Installation does not prove that the coding agent loaded the skill.
  3. Routing starts with procedures. The previous skill opened a menu after context and audit. The local revision now starts from the problem, diagnoses it and recommends a bounded plan; the published package has not been updated by this work.
  4. Completion differs by branch. A first foundation, an adoption repair, and a review must not all end at “audit clean.”
Boundary rules and evidence receipt
  • “No system,” “partial” and “established” are evidence-informed situations, not scanner verdicts. Different areas in one company can take different branches.
  • No code yet: use product needs and a representative prototype. Unsupported syntax: inspect manually or use an appropriate existing checker.
  • Existing authority wins over invented defaults. Resolve conflicts with the owner; do not infer permission from current code.
  • Shared or breaking changes need the project's ownership and release process. Reuse existing authorization for bounded work.
  • Receipt separates engine checks, browser/test evidence, human judgments, and unchecked behavior. Name the method and source for each.
  • Store next action and unresolved owner in the existing issue/task. Link decisions from the project's ADR or contract. No engine conversation-state store.
  • File scope and severity scope are independent. A scoped audit can still be unfiltered by severity; read required token dependencies separately before relying on cross-file rules.
  • Leaving code unchanged can finish an investigation. Missing evidence produces a stated gap, not a pass.

Diagnosis before choosing a route

Understand the requested outcome → investigate a concrete example → explain the cause and uncertainty → recommend a bounded delivery with a finish line. Scale the conversation to the request.

Optional specialist: Storybook Architect

DS Loop: basic Storybook setup when appropriate—configuration, themes, a representative story and usage guidance, with start/build checks.

Deeper management: identify the task → check whether storybook-architect is available → load it, or offer installation from a verified source → pass existing context and scope → complete the specialist work → return evidence to DS Loop.
