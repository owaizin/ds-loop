## 3. Wire reachability into the HTML report

Section F's evidence exists in `--json` and terminal output. **The HTML report does not show
it at all** — `grep -c reached` returns 0 in every renderer.

New `AuditReport` fields available: `fileImports`, `findingEvidence`, `findingTotals`,
`reachedStyleInventory`, `reachedRatios`.

The rule that governs the display, carried over from the engine: **every visible count is
paired with its reached count.** One is never shown without the other. Annotating findings is
allowed; removing them is not, because absence is never a pass and a tool that silently drops
findings has numbers nobody can audit.

The wording is fixed and not a style choice: **"no static importer found"**. Never *dead*,
never *unused*, never *safe to delete*. A test pins those strings out of the output.

This touches the report thread's files. Sequence it with that thread.

## 6. Smaller, genuinely optional

- **`doctor`'s intent check is narrow by design.** It matches whole-line convention sentences
  from `config.taxonomy.conventionStatements`. It prints the sentences it looked for and says
  finding none is not a pass. Widening the list widens what the tool claims to have checked —
  a wrong "your docs are out of date" costs more than a quiet one.
- **Reached documentation ratios are `null`, deliberately.** Documentation presence is not a
  file-import metric, and a fabricated zero would be worse than an absent number.
- **Aggregate findings without complete source provenance stay `unresolved`.** Phase 12 chose
  not to guess membership from a truncated display string. That is the right call; revisit
  only with real provenance.

## The constraints that do not move

From `CLAUDE.md`, and each one is here because it was learned from a defect:

- No model call, no network, no runtime dependency in `src/`.
- No threshold outside `src/config/`. A phrase list is policy too.
- `clean` / `issues` / `not-checked` stay distinct. **Absence is never a pass**, and a clean
  verdict is only as wide as its coverage.
- Ratio keys and rule ids are **stable** — scorecard rows and the calibration corpus key on
  them. Add keys beside; never redefine one in place.
- Ratios, not counts, as headline numbers.
- Never rebrand CLI output. `ds-loop audit — <label>` is checked against real runs.
- Documented output must be real output: run the command and paste it. Editing a sample to
  make a test pass removes the guard against fabricated samples.
- **No client names or engagement measurements in this repo, ever.** Examples are "Example DS"
  and `--ds-*`. This was violated once and repaired with a history rewrite.
- Do not rename `ds-loop`, `.ds-loop-config.*`, `.ds-ops-config.*`, `.ds-scorecard/history.jsonl`,
  `skill/hooks/ds-loop-guard.mjs`, `node_modules/.cache/ds-loop/`.
- Run `git identity` before commits. Personal (`owaizin`) is default here.
