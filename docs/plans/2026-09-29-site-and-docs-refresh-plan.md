# Plan: bring the site and the guide up to what the tool actually does

Written 2026-09-29. The engine moved from 0.2.0 to 0.4.0 across seven build phases plus the
adoption surface. The site did not move with it, and parts of it are now not merely dated but
wrong.

## The gap, measured

| | Site says | Actually true |
|---|---|---|
| Version | 0.2.0 published, 0.2.1 in source | 0.4.0 |
| Adapters | 2 — CSS custom properties, Tailwind JSX | 5 — plus CSS rule bodies, token JSON (W3C DTCG + Style Dictionary), SCSS |
| CLI commands | 7 | 15 |
| Agent commands | none | 12 |
| Consulting report | absent | `ds-loop report` — the main deliverable |
| Dashboard | absent | `ds-loop dashboard` |
| Benchmark | absent | 11 pinned public repos with a sample floor |
| Roles and practices | absent | 8 roles, 6 cited practice guides |
| Install | "read this path into your agent" | `ds-loop install` writes the block |

Two statements are **actively false**, not just stale, and both are in `site/reference.html`:

- "Sass maps, design-token JSON and unsupported formats remain outside these adapters." Both now
  have adapters. A reader deciding whether the tool fits their SCSS codebase is told no, wrongly.
- The adapter table lists two adapters as the whole coverage surface. Coverage is the product's
  central honesty claim, so a wrong coverage table is the worst single line on the site.

Twelve version strings across four pages say 0.2.x. `docs/guide/release-0.2.0.md` is a release note
for a version two minors back.

## The structural finding

`test/readme.test.ts` verifies documented samples against real runs — but only for `README.md`,
`docs/guide/output.md` and `docs/site/landing-copy.md`. **The site's HTML is outside that net**, and
`site/reference.html` carries nine `ds-loop audit` samples nothing checks.

That is how a sample composed from memory shipped once before, which is why the test exists at all.
The site is currently the one surface where it could happen again undetected. Extending the checker
to the site is worth more than any copy change in this plan, because it is the only part that keeps
being true after everyone stops paying attention.

---

## A. `site/` — the marketing and reference pages

Owner: one Codex thread. Touches `site/**` only.

1. **`reference.html` — the coverage table first.** All five adapters, each with what it reads and
   what it does not, taken from the adapters' own `extensions` and `reads` fields rather than
   written from memory. Delete the Sass/JSON exclusion sentence.
2. **Command reference — all 15**, in the groups a reader thinks in rather than alphabetically:
   look (`start`, `context`, `audit`, `scan`, `sweep`, `consumers`, `impact`), deliver (`report`,
   `dashboard`, `scorecard`), change (`fix`, `decide`), wire up (`install`, `guard`), and whatever
   E adds. Keep the existing Result/Writes columns: "what it writes" is the question a reader
   actually has.
3. **A new section for the twelve agent commands**, typed `/ds-loop:start` — the namespaced form,
   not the space form, which does not exist. Say plainly that these are the agent layer and the CLI
   is the instrument layer, and that the CLI names never change.
4. **Version strings.** Twelve of them, across `index.html`, `docs.html`, `setup.html` and
   `reference.html`. Source the number from `package.json`; do not retype it.
5. **`setup.html`** leads with `npx ds-loop` then `ds-loop install`, not with a path to paste.
6. **`index.html`** gains the report and the dashboard. They are the deliverable a lead forwards,
   and the site currently does not mention either.

**Do not** restyle. The visual design is not in scope and a redesign inside a content pass is how
this becomes unreviewable.

## B. `docs/guide/` — the written documentation

Owner: a second Codex thread. Touches `docs/guide/**` only. No overlap with A, which is why the two
can run at once — the same boundary `CLAUDE.md` already draws between the site task and the
documentation task.

1. **`reference.md`** — the same coverage and command truth as A, at the depth a reference wants:
   configuration keys including `clustering.alphaTolerance`, the three verdicts, the instrument-
   comparison rule, `not-checked`.
2. **`install.md`** — `ds-loop install`, what it writes, where, and that it never overwrites.
3. **`output.md`** — samples for `report` and `dashboard`, **generated by running the command and
   pasting**, marked `verified:` and registered in `test/readme.test.ts`. Never composed.
4. **`workflow.md`** — the twelve agent commands and where roles and practices fit.
5. **`release-0.2.0.md`** — supersede with a 0.4.0 note, or delete. Do not leave it as the newest
   release note in the directory.
6. **`benchmark.md`** already exists and is current; check it, do not rewrite it.

## C. Put the site inside the verification net

Small, and the only item here that stops this plan being needed again.

`test/readme.test.ts` already extracts `verified:` blocks and runs the command behind each one.
Extend the file list to include `site/reference.html`, with the marker written as an HTML comment.
Nine existing samples then either prove themselves or fail the build.

If a sample turns out to be stale, **regenerate it by running the command**. Editing a sample to
match, or dropping its marker, removes the guard and leaves the fabrication.

---

## Order

**A and B run in parallel** — different directories, no shared files. **C after B**, because B adds
the samples C will check.

## Constraints, from `CLAUDE.md`

- **Writing standard is `mattpocock/skills`**: hook then problem then fix, a runnable command in the
  first ten lines, install and use before architecture, direct address, confident and unhedged, real
  output only. Limits go in a dedicated section, stated plainly, not apologised for throughout.
- **Never rebrand CLI output.** `ds-loop audit — <label>` is checked against real runs.
- **Cite a source for the specific claim it supports.** A named source beside an unsupported
  generalisation is how this project once shipped comparative claims nothing backed.
- **No client names, no engagement measurements.** Examples are "Example DS" and `--ds-*`.
- Keep the two layers: rule ids, `--json` and fix text stay precise; human-facing text is plain.
- Say `clean` / `issues` / `not-checked` as three outcomes. Absence is never a pass.

## Verify

`npm run check && npm run type-check && npm test`, then open every changed page in a browser at
375px and desktop width. `file://` is blocked for the browser tools — serve it:
`cd site && python3 -m http.server 8899`.

The acceptance test a test cannot run: read `reference.html` as somebody deciding whether this tool
reads their SCSS codebase, and see whether the page answers them correctly.
