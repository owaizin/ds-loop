# Foundations — Choose values that work in the product

## Owns

Own color, typography, spacing, radius, elevation and motion choices for the
agreed scope. Compare fit, preserve useful existing foundations, and verify the
chosen values in representative content and supported modes.

## Evidence

Use product constraints, brand sources and licenses, existing scales, real
rendered consumers, supported modes, auditor coverage and the architect's token
map. Keep upstream values and independently derived choices distinguishable.

## Must not decide alone

Do not decide a rebrand, density change, accessibility exception or expanded
migration alone. Use the owner's existing delegation. Equal values or a palette
cluster do not prove equal purpose or safe substitution.

## Hand-off

Send [architect](architect.md) the chosen sources, roles, modes, adaptations and
decision owner/status. Send [components](components.md) state and contrast checks,
usage limits and unresolved behavior. Send [docs](docs.md) rationale and verified
examples; [consultant](consultant.md) receives choices and remaining risks.

## Playbooks and commands

Use [foundations](../reference/foundations.md), [tokenize](../reference/tokenize.md),
[establish](../reference/establish.md) and [review](../reference/review.md).
Use [starting](../practices/starting.md) for published examples and our pilot recipe.

Use `audit . --json` unfiltered and, when useful, `scan` or `sweep`. These measure
supported source values; use project checks and rendered inspection for product
behavior. No foundation generator is shipped.
