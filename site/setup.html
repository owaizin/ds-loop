Set up
Design System Loop.

Install the package, load the skill in your coding agent, and describe what you need. Your agent investigates the repository and guides the next steps.

Before you start

You’ll need Node 22.6 or later and npm. For the companion skill, use a coding agent that can read local files and run terminal commands. Start in an isolated checkout of the project you want to inspect.

The CLI checks CSS custom-property declarations, Tailwind arbitrary values, and selected named-palette utilities in JS/TS when token context is available. Your agent uses the companion skill to investigate findings and work with your project’s conventions. Check the supported scope.

1. Install the package

Run this in your project directory to install Design System Loop 0.2.0 from npm. To try the expanded 0.2.1 setup procedure before publication, use source installation.

Terminal · your project directory
npm install --save-dev ds-loop@0.2.0

The package includes the CLI and the companion skill at node_modules/ds-loop/skill/SKILL.md. Installing it does not load the skill into your agent or enable ongoing maintenance. Load the skill in step 2.

2. Load the skill

Open your coding agent in the project where you installed the package. Paste this prompt and describe your problem. The agent runs the relevant checks; you do not need to interpret an audit before starting.

Agent prompt · add your product and problem
Read node_modules/ds-loop/skill/SKILL.md and follow it throughout this task. Confirm the installed version.

I need help with our design system. Start by asking what problem we need to solve, unless I have already explained it. Inspect the repository, existing components, conventions, and representative workflows.

Explain what exists, what is missing, and what you could not verify. Ask only about unknowns that would change your approach. Recommend a delivery with clear outputs and a finish line. Start read-only.

You should receive: a diagnosis grounded in your project, a recommended scope, and questions about decisions the agent cannot infer. Installing the package alone does not start this conversation.

Keep the whole package installed. The skill needs the adjacent bin/ and dist/ directories. Asking the agent to read the file directly avoids relying on automatic skill discovery.

3. Agree on the delivery

For a full setup, the plan should cover foundations, components, product patterns, a working reference, and maintenance guidance. It should name the workflows that will use them and the behavior to preserve. A proposal-only request should remain read-only.

Expanded setup in 0.2.1: the full establishment procedure is in the source checkout and is not yet on npm. Use source installation to evaluate it. The npm command above installs 0.2.0.

When the scope is right, authorize the work. If you already provided a clear task and permission, the agent should continue without asking again at every step.

Agent prompt · after reviewing the plan
Proceed with the agreed plan. Implement and adopt the system across the agreed workflows, verify the affected behavior, and document how developers use, customize, and extend it.

Make routine decisions within that scope. Ask when missing information or a wider change needs my decision. Keep me informed of what is done, what comes next, and what remains. Continue through the agreed delivery, not only its first example.

Use the Start, Improve, and Maintain examples for a more specific task. These are examples to adapt, not commands you must learn.

Review the result

A useful handoff distinguishes delivered work from the checks supporting it. It names the relevant files, failed or unrun checks, the saved decision, and the next useful step. A finished audit does not mean the product change is complete. See the skill’s progress and completion examples. Compare it with the worked example.

I only want to run the engine.

You can run deterministic checks without a coding agent. From the project directory:

Terminal · optional direct checks
./node_modules/.bin/ds-loop context .
./node_modules/.bin/ds-loop audit . --json

context reports configuration and extraction scope; it runs no rules. The unfiltered audit supplies findings and judgment limits. Read verdict and coverage: exit 0 alone does not mean the input was checked.

The audit returned findings. Did setup fail?

Findings are an audit result. Exit code 1 is expected when findings are present. Read the report before deciding whether the code needs to change; a finding can reflect an intentional exception or a checker limitation.

The report says “not-checked”.

The engine did not check that input with its supported adapters. Reinstalling won’t add coverage for an unsupported format. Read coverage and limitations, then have your agent inspect the relevant source another way.

My agent cannot find the skill.

Check that the agent is working in the project where you installed the package. Ask it to read node_modules/ds-loop/skill/SKILL.md directly. Install the full package rather than copying only the skill folder.

Install from source

Use this route to try the current source. Clone into a separate directory, then verify the version and build an archive. If you already have the source checkout, use it directly. Packing does not publish it:

git clone https://github.com/owaizin/ds-loop.git
cd ds-loop
npm pkg get version
npm ci
npm pack

The current source version is 0.2.1, which produces ds-loop-0.2.1.tgz. Install it in the project you want to inspect using its actual absolute path:

npm install --save-dev /absolute/path/to/ds-loop-0.2.1.tgz

Then load node_modules/ds-loop/skill/SKILL.md as in step 2. Version 0.2.1 adds the expanded establishment procedure. Its engine checks are unchanged from 0.2.0. A local tarball path is machine-specific; use the matching npm release when it is published before asking teammates to install it.

Local tarballs rebuilt under 0.1.2 can differ from registry 0.1.2. Check the dependency’s resolved artifact and integrity in the lockfile, not only the version string. Run an unfiltered audit after upgrading and review coverage before comparing measurements.
