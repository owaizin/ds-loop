Technical reference.

Use this when you need a command, a configuration option, or the exact limits of a check.

Version 0.2.0. This reference describes the published npm engine. The same excerpts are checked against local 0.2.1 source, whose engine is unchanged; its new setup procedure belongs to the agent skill. Install from npm, or build from source for local development.

Coverage and limitations

Adapter Reads Does not read
CSS custom properties Custom-property declarations in .css Ordinary rule bodies and declarations inside at-rules
Tailwind JSX Arbitrary-value strings and selected framework-palette color utilities in .jsx .tsx .js .ts .mjs (adapter 0.4.0) Project-defined named utilities, arbitrary variants, bracketed opacity, inline styles and CSS-in-JS. No Tailwind theme resolution.

Sass maps, design-token JSON and unsupported formats remain outside these adapters. Recognized colors that cannot be converted are reported as ambiguous. The engine uses regex-based extraction with documented limits.

Read the verdict with the coverage

  • clean: no findings survived the selected scope and severity. Read coverage before interpreting this result.
  • issues: findings survived. Some checks may still have been unable to judge.
  • not-checked: no adapter read a source, including an empty source.

Severity filtering does not remove coverage.couldNotJudge. The hook filters at high severity and context runs no rules. Run an unfiltered audit to see all judgment limitations.

Current status

Design System Loop is a supervised alpha. Start in an isolated checkout, choose an area to review, and check the result before wider adoption. Findings and ratios describe extracted source. They do not establish design intent, system maturity, accessibility or user outcomes.

Command reference

Run commands from the target project so configuration resolves from its working directory. A positional path selects the source. For a local npm installation, replace ds-loop below with ./node_modules/.bin/ds-loop.

Command Result Writes
context [path] Configuration, usual intent-source paths and extraction scope. Runs no rules. Only with --write-contract; never overwrites
audit [path] Findings, ratios, verdict and coverage. With --out
scan <path> Extracted-value taxonomy and palette clusters. No
sweep <path> Clustering curve across the configured ΔE range. With --out
scorecard [path] Ratios and comparable deltas. Not a CI gate. Appends local history; --dry-run previews
fix <path> Mechanically resolvable var() fallbacks. Only with --write
guard on|off|status Claude Code post-edit feedback configuration. on/off edit settings

scorecard appends to .ds-scorecard/history.jsonl in cwd. It reports a delta only when adapter versions and configuration match. fix is not an automatic token migration.

Preview a mechanical fix

ds-loop fix . --help
ds-loop fix .
ds-loop fix . --write
ds-loop audit .

Review the preview before choosing --write. The fixer inserts missing var() fallbacks only in CSS custom-property declarations whose referenced token has a direct color or dimension literal in scope. It does not follow alias chains or migrate JSX utilities. A zero-edit result explains why nothing was eligible; it does not mean the audit is clean. --target is an audit option, not a fix option.

Draft a contract

ds-loop context . --write-contract

This creates DESIGN-SYSTEM.md with measured declarations, extraction limits, recorded exceptions, and questions the team still needs to answer. It never overwrites an existing file. Keep your existing decision home when it already works. The draft does not establish policy; an agent must read and apply your decisions. Editing it does not configure or suppress rules.

Audit options

ds-loop audit . --json
ds-loop audit src/ --target tokens
ds-loop audit . --files src/tokens.css,src/Card.tsx
ds-loop audit . --since main --min-severity high
ds-loop audit . --out ./audit-report
ds-loop audit . --require-coverage

Targets are all, tokens, color, spacing, typography, elevation and motion. Use an unfiltered audit when you need the complete findings list.

--files selects paths relative to the working directory. --since main selects committed changes from the merge base to HEAD; it excludes uncommitted edits. An empty selection returns not-checked. A failed Git comparison stops the command.

Agent procedures

discover, census, drift, tokenize, scaffold, extract, shape, review and doctor are playbooks. An agent executes them. They are not CLI commands or deterministic findings.

Configure the checks

Automatic discovery checks these filenames, in order, in the current working directory:

.ds-loop-config.yml
.ds-loop-config.yaml
ds-loop.config.json
.ds-ops-config.yml
.ds-ops-config.yaml

The explicit --config <file> option currently reads JSON. Auto-discovered YAML uses a limited parser rather than the full YAML specification.

Represent the project’s naming

If your actual contract uses --foundation-* primitives and --intent-* semantics, an illustrative ds-loop.config.json is:

{
  "taxonomy": {
    "primitivePattern": "^--foundation-",
    "semanticNamespaces": ["intent"]
  }
}

Use patterns from your own contract. A config entry configures an existing rule; it does not create a checker. The engine’s palette → semantic → component assumption is not a universal architecture. Report a limitation when your model cannot be represented faithfully.

Clustering cutoffs and taxonomy defaults are uncalibrated. Use sweep to investigate the source before choosing a cutoff. See the configuration schema and defaults.

Token context

token/stock-palette-utility reports selected framework-palette utilities such as bg-white when applicable color declarations exist. A finding asks you to check the project's theme and contract; it does not establish the rendered color or a contrast failure.

Use JSON to associate consumers with the CSS declarations they use:

{
  "tokenContexts": [
    { "files": ["app/*"], "tokens": ["app/theme.css"] }
  ]
}

These paths are relative to the audit source root, or the containing directory for a single-file audit. files supports exact paths and trailing-* prefixes. tokens names exact CSS files inside that root. The declarations supply context without adding out-of-scope findings or changing ratios.

Once you add a mapping, every stock-palette use site in the audit scope needs applicable, readable context. Unmapped consumers become unjudged, including in a full-tree audit. --require-coverage fails on those gaps even if a severity filter hides the related finding. Without mappings, an unscoped audit uses any color declaration in its target as a broad context gate.

Mappings do not resolve CSS imports or Tailwind themes. JSON reports retain context paths, consumers, hashes, and read failures in manifest; mappings change configHash. The YAML subset cannot represent these entries. Migrate a higher-priority YAML configuration into JSON, or select JSON with --config. The hook uses automatic discovery.

Record an exception

Add a verified exception to the project's existing JSON configuration, with the reason and intended scope:

{
  "ignore": [
    {
      "rule": "color/semantic-holds-literal",
      "value": "--color-surface-raised",
      "files": ["theme.css"],
      "reason": "This token seeds the palette layer planned for next sprint.",
      "createdAt": "2026-09-19"
    }
  ]
}

reason is required. rule accepts a rule ID or *; value matches a token name, literal, or *. Omitted files covers all files; files: [] matches none. Paths match exactly or by suffix, so theme.css also matches legacy/theme.css. A trailing * matches a prefix from the audit source root; interior wildcards are unsupported. Invalid scopes fail configuration loading.

ds-loop audit . --json

Run this before and after the config edit. Check suppressions for the intended rule, value, and matched count, and confirm unrelated occurrences remain visible. Exceptions remove matching values from that rule's input and change configHash. A lower finding count caused by an exception records a policy choice, not a repair. The report keeps matched exceptions visible even when the verdict is clean.

After an upgrade, rerun an unfiltered audit. Adapter 0.4.0 changes extraction, and changed adapter versions or configuration hashes can make scorecard measurements incomparable.

The .ds-ops-config.yml compatibility path reads system context and maps supported severity settings from design-system-ops.

Edit feedback and CI

Feedback during Claude Code edits

./node_modules/.bin/ds-loop guard on
./node_modules/.bin/ds-loop guard status
./node_modules/.bin/ds-loop guard off

The PostToolUse hook reports high-severity findings after supported edits and announces changes in project extraction coverage. It never blocks an edit. guard off removes its entry while preserving other hooks and settings.

The hook does not deliver lower-severity judgment limitations. Run an unfiltered audit at session setup and before calling a change complete.

In 0.2.0, hook failures and timeouts explicitly report that the edit was not checked. Correct the error and rerun the audit. The default high-severity hook also filters out the medium-severity palette rule.

Choose a CI policy deliberately

./node_modules/.bin/ds-loop audit . --min-severity high --require-coverage

This exits 1 on findings at the chosen floor or reported coverage gaps. A pass applies to the adapters’ stated scope and selected severity. Inspect unsupported formats before enabling strict coverage.

Reproduce the examples

These four synthetic cases are reproduced from local engine 0.2.1, unchanged from 0.2.0. This website does not scan your repository.

From this checkout, run npm run site:check to run the four audits against this checkout’s engine in temporary directories and compare their output with the saved website examples. Release verification also checks these excerpts against the published npm archive. The inputs and excerpts are also available as plain JSON.

A hardcoded value

tokens.css

:root {
  --palette-blue-500: #1da1f2;
  --brand: var(--palette-blue-500, #1da1f2);
}

Card.tsx

export const Card = () => (
  <div className="bg-[#1da1f2] p-[13px]">
    <span className="text-[14px]" />
  </div>
);

Engine output excerpt

  [HIGH] token/raw-value-in-markup
    3 hardcoded value(s) at use sites bypass the token layer (1 colour, 2 length; 3 distinct, 1 already declared as a token)
    where: bg-[#1da1f2] at Card.tsx:2; p-[13px] at Card.tsx:2; text-[14px] at Card.tsx:3
    risk:  The value is invisible to every theme, rebrand and audit that reads the token files — a rebrand ships and these sites keep the old colour.
    fix:   #1da1f2 is already --palette-blue-500. Swap those first. Replace each with the scale step or token that covers it — a utility that names the scale (bg-surface, p-4) or var(--token) via an arbitrary value. If no token matches the value, add one to the system first; a bracket is the system being bypassed, not extended.
A naming pattern the scanner cannot judge

tokens.css

:root {
  --ocean: #1da1f2;
  --link: var(--ocean, #1da1f2);
}

Engine output excerpt

  [LOW] token/tier-model-undetectable
    only 0 of 1 referencing token(s) match a tier pattern (0 < floor 0.5) — tier checks could not judge this source
    where: --link
    risk:  A clean `token/tier-leakage` result in this source means nothing was checked, not that nothing is wrong — the strongest silent-pass this tool can produce.
    fix:   Set taxonomy.primitivePattern, semanticNamespaces and componentPattern to this source's naming convention, then re-run. Until then treat a clean token/tier-leakage result as "not checked", not "passed".

A framework-palette utility with explicit token context

theme.css

:root {
  --palette-blue-500: #2456ab;
}

Card.tsx

export const Card = () => <div className="bg-white">Account</div>;

ds-loop.config.json

{
  "tokenContexts": [
    {
      "files": [
        "Card.tsx"
      ],
      "tokens": [
        "theme.css"
      ]
    }
  ]
}

Engine output excerpt

  [MEDIUM] token/stock-palette-utility
    1 use site(s) name the framework palette instead of a theme token (1 distinct across 1 file(s))
    where: bg-white at Card.tsx:1
    risk:  Bypassing theme roles can leave surfaces in the wrong mode or text with insufficient contrast when the theme changes.
    fix:   Check the resolved framework theme and project contract. Where a semantic role applies, use its utility (for example bg-surface or text-muted-foreground). This audit checks structure, not rendering: confirm the swap in the browser in both modes.
