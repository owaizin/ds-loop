When every team rebuilds the same patterns

One team builds a table. Another writes its own version. An AI-generated screen adds a third set of spacing values. Soon, changing a pattern means finding and updating several implementations.

Design System Loop helps your team build what is missing, reuse what works, and leave guidance the next developer can follow. Your coding agent leads the work with the skill; the engine supplies repeatable code checks.

From your problem to working code

Tell your agent what needs to become easier. It investigates the repository, recommends a scope, and carries the authorized work through to a checked result.

  1. Understand the problem

    Read existing components and decisions. Inspect the product and ask about constraints that could change the plan.

  2. Build and adopt the system

    Reuse a suitable base, fill the gaps, and connect shared components to the agreed workflows. A first example is a checkpoint in a broader setup.

  3. Verify and hand it over

    Check the affected behavior. Leave a working reference, maintenance instructions, and a clear account of what remains untested.

Before you start

What should a setup deliver?

Editable foundations, reusable components, product patterns used in the agreed workflows, and a guide for using and changing them. The expanded setup procedure is in the 0.2.1 source; npm currently serves 0.2.0. Try the expanded setup from source.

Do we need a design system already?

No. Your agent starts from your product’s needs and chooses a suitable foundation. If you already use a library, it should investigate and extend it before proposing a replacement. The component set follows the agreed scope.

What do the skill, engine, and team each do?

The skill guides your coding agent through diagnosis, implementation, verification, and handoff. The engine checks supported token and styling code. Your team sets priorities, resolves consequential design decisions, and controls releases. Installing the package does not activate the agent.

Does it replace shadcn/ui or require Storybook?

No. It can use a suitable component library as the base and preserve your existing documentation environment. A basic component reference may be enough. Deeper Storybook work can go to an available specialist, which is not bundled with this package.

When is the work finished?

The agreed workflows use the shared system, the relevant checks have run, and the handoff explains how to use and extend the result. A gallery or clean audit alone does not demonstrate completion. Unverified behavior must remain visible.

What does it check automatically?

The engine reads CSS custom-property declarations and selected Tailwind arbitrary values and stock-palette utility names in JavaScript and TypeScript. It does not review layouts, interactions, accessibility, or design quality. Read the exact coverage.

Does it work in the background?

No. A person or agent starts each task. The optional Claude Code hook reports after supported edits; it cannot block or repair them. CI checks are a separate, deliberate setup. Design System Loop remains a supervised alpha: review the work and its evidence.

What does it cost, and where does our code go?

The package and skill are open source under MIT. The engine runs locally without model calls, API keys, or runtime network access. Your coding agent’s costs and data handling depend on its provider and your settings.
