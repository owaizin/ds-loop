# Design System Loop

Design System Loop helps teams establish a usable design system, improve inconsistent implementations, and maintain shared foundations as their product grows. The customer should receive working source, adoption in real workflows, guidance for using and changing it, and evidence of what was verified.

## Audience and problem

Designers, frontend engineers and design-system teams working on evolving products. Teams repeatedly rebuild controls, forms and tables, struggle to discover the right implementation, or find that shared styles are difficult to change safely. Diagnose the cause before recommending a migration. Different areas can need different interventions; scanner silence is not a maturity score.

## Working process

The coding agent loads the skill, understands the user's problem, inspects the repository and product, recommends a delivery, and executes authorized work. It asks about unknowns that could change the plan and continues routine work within the existing permission. The engine supplies evidence; it does not interview users or decide product priorities.

- **Establish:** choose a compatible base; deliver foundations, components, product patterns, a live reference and maintenance guidance across the agreed workflows. A first example is a checkpoint unless a pilot was requested.
- **Improve:** investigate gaps in capability, adoption, discovery or conventions. Repair the demonstrated cause or retain a justified difference.
- **Maintain:** review or extend existing contracts, verify affected consumers, and update decisions where the team already works.

Completion reports delivered work, actual checks, unverified behavior, and a continuation path. A later contributor should be able to find the guidance and use, customize and extend the result. A gallery or lower finding count alone does not prove completion.

## Product truth

The deterministic engine has eight CLI commands and twelve rules. It reads CSS custom-property declarations and selected Tailwind arbitrary values and stock-palette strings in JavaScript and TypeScript. It does not resolve the full framework theme, check ordinary CSS rule bodies, or review the rendered experience. It has no runtime dependencies, model calls, API keys or runtime network requirement. Node 22.6 or later is required.

The skill's procedures are instructions for a coding agent, not additional CLI commands. Installing npm does not activate the agent. The optional Claude Code hook reports after supported edits and cannot block them; CI gating is a separate configuration. No automatic background maintenance is provided.

The package and skill are MIT licensed. Agent usage costs, tool access and provider data handling are separate. The team retains design direction, shared-policy decisions and release authority.

## Evidence and quality bar

Design System Loop remains a supervised alpha. Synthetic setup and continuation trials support specific outcomes, not a broad reliability or visual-quality advantage. All public examples are synthetic or open source. No client identifiers, source, paths or engagement measurements belong in the repository or website. Do not invent endorsements, savings or adoption figures.

The reader should understand the outcome, distinguish agent and engine responsibilities, install the available version, explicitly load the skill, and know what to review. Verify the website on desktop and narrow screens, with keyboard controls, and preserve reduced-motion and no-JavaScript behavior. Source checks do not establish user comprehension or a full accessibility audit.
